# Релизы

## Правила версий

- **Стабильный тег:** `v<versionName>`
- **Предварительный:** `v<versionName>-<suffix>`
- `applicationId`: `com.makriq.flclash`

## Состав релиза

- `FlClashM-android-universal.apk`
- `FlClashM-android-arm64-v8a.apk`
- `FlClashM-android-armeabi-v7a.apk`
- `FlClashM-android-x86_64.apk`
- `FlClashM-android-release.aab`

Каждый релиз содержит `.sha256` для каждого файла. Для стабильного релиза их
наличие дополнительно считается обязательной частью выпускного контракта.

## Конвейер

1. Проверка границ продукта, расхождений с апстримом, тестов и анализа
2. Проверка непрерывности выпуска
3. Сборка артефактов
4. Проверка подписи всех APK и AAB
5. Генерация метаданных
6. Генерация контрольных сумм
7. Формирование и подпись каталога обновления Ed25519
8. Публикация APK и каталога на SourceForge
9. Публикация на GitHub

## Доставка обновлений приложения

SourceForge `flclashm` является основным каналом доставки APK, GitHub —
запасным. Приложение читает фиксированные указатели:

- `https://flclashm.sourceforge.io/update/stable.json`
- `https://flclashm.sourceforge.io/update/pre.json`

Для каждого указателя рядом публикуется двоичная подпись `.sig`. Подпись
проверяется встроенным открытым ключом Ed25519 до разбора JSON. Каталог содержит
SHA-256 и упорядоченный список зеркал каждого ABI APK. Заголовки поставщика не
используются для определения доверия.

Файлы выпуска сначала загружаются в неизменяемый каталог
`releases/<tag>`. Затем публикуется подпись указателя и последним — сам
указатель. Для выпуска нужны тайны `APP_UPDATE_SIGNING_KEY`,
`SOURCEFORGE_SSH_KEY` и `SOURCEFORGE_USERNAME`.

Приложение запоминает наибольшие `versionCode` и время публикации отдельно для
каждого канала и отвергает повтор старого подписанного каталога. Поэтому откат
выполняется только новым исправляющим выпуском с большим `versionCode`; уже
установленный APK также нельзя понизить средствами Android. При смене ключа
каталога сначала выпускается переходная версия приложения с новым открытым
ключом.
