# Windows x64: runtime и проверка

Рабочая ветка — `feat/windows-desktop`, PR направлен в `feat/cross-platform`.
Слияние PR и выпуск тега выполняются отдельно после проверки.

## Архитектура и контракт

GUI и обычный прокси остаются пользовательскими процессами. При включении TUN
ядро перезапускается через службу, при выключении — возвращается к запуску GUI. Установщик Inno Setup с UAC
устанавливает LocalSystem-службу `app.flclashm.client.helper` в фиксированный
`%ProgramFiles%\FlClashM`. Named pipe допускает только локальные подключения;
служба проверяет PID и точный путь установленного `FlClashM.exe`, а GUI — путь
службы и её LocalSystem SID. Чтение/запись имеют ограниченное время ожидания.

Служба принимает `ping`, `runtimeStart` и `runtimeStop`. Запуск разрешён только
для установленного `runtimes/windows/x86_64/mihomo.exe`; параметры — порт GUI
и случайный 256-битный секрет аренды. Порт должен принадлежать вызывающему GUI.
Пути, shell, argv и переменные окружения клиентом не задаются. Секрет подтверждает
подключение ядра к управляющему сокету. Одновременно действует одна TUN-сессия;
другая пользовательская сессия не может остановить чужую аренду.

Маршруты, DNS и адаптер `FlClashM` создаёт и освобождает Mihomo. Отдельные операции
helper для изменения сети отвечают `unavailable`. Закрытие управляющего сокета
или stdin запускает штатную очистку ядра. Служба отслеживает завершение GUI;
после пяти секунд применяется принудительное завершение. Job Object ограничивает
время жизни всего дерева процессов жизнью службы.

Домашний каталог привилегированного ядра — `{app}\service-data\<SID>` с доступом
только SYSTEM и Administrators. Профили и file providers читает GUI со своими
правами и передаёт байты; ядро сохраняет providers по хешированным именам.
Сохранение HTTP-загрузок также выполняет GUI. В режиме TUN привилегированный внешний
controller и external UI отключены; сертификаты должны передаваться inline PEM.
Локальные providers ограничены 16 MB на файл и 32 MB на один план.

Portable-запуск без установленной службы поддерживает обычный прокси.
Для TUN требуется установка полной версии. Ядро и helper обновляются только
вместе с приложением; отдельная подмена mihomo на Windows запрещена.

## Обновление и откат

Полный установщик проверяется по подписанному Ed25519-каталогу и SHA-256.
После принятия UAC GUI выполняет очистку сети и выходит. Setup ждёт GUI и
watchdog, сохраняет предыдущий каталог приложения и восстанавливает его при
ошибке. Данные GUI и защищённый кэш ядра сохраняются по умолчанию.
Установщик не подписан Authenticode; обход SmartScreen не выполняется.

## Проверка

Windows CI собирает runtime, helper, приложение и Inno installer. Проверяет
системный прокси, установку/удаление службы и отказ постороннему IPC-клиенту.
Сборка CI с `FLCLASHM_WINDOWS_E2E=true` дополнительно запускает установленный GUI
через `--windows-runtime-check <файл-результат>`: настоящий service/IPC путь,
создание, остановку и повторный запуск TUN. `--hold` оставляет TUN активным для
проверки падения GUI и остановки службы. В обычном выпуске этот вход отключён.
Маршрут опыта ограничен `198.18.0.0/24`; default route CI не меняется.

Перед первым выпуском проверить на физических Windows 10/11: UAC, реальные
профили со встроенными узлами, IPv4/IPv6, смену Wi-Fi, сон/пробуждение, default
route TUN, обновление с отменой UAC и восстановление предыдущей версии после
ошибки. Windows Server runner не подтверждает эти сценарии.

## Первый кандидат

Подготовлен `0.4.0-pre1+2026101201`, будущий тег — `v0.4.0-pre1`.
Windows CI выдаёт установщик без тестового входа и его SHA-256 в артефакте
`FlClashM-windows-x64-preview`. Это кандидат для ручной проверки, а не
опубликованный релиз. После проверки Windows 10/11 нужно отдельно разрешить
слияния и поставить тег на `main`; релизный процесс опубликует установщик и
подписанный desktop-каталог. До этого production-указатели обновлений не меняются.
