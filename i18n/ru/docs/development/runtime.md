# Среда выполнения

Go компилирует профиль в неизменяемый план. RuntimeCoordinator управляет mihomo,
VPN и отдельными процессами NaiveProxy, OlcRTC, ByeDPI и StormDNS.
Контракты состояния и восстановления — в [Go backend](go-backend/architecture.md).

## Запуск и остановка

`ui.attach` позволяет Go заранее подготовить профиль и обычные внешние узлы
без включения VPN. При Start готовый план переиспользуется после проверки
процессов. Потерянный процесс требует восстановления; узлы с `activation: auto`
сохраняют правила сна и пробуждения.

Stop отменяет подготовку и выключает VPN. Уже подготовленные обычные узлы могут
остаться для проверки задержки при открытом приложении. Это не намерение
подключения: восстановление после Stop не запускает их заново. Reset и закрытие
backend завершают все процессы.

## Внешние узлы

Узлы объявляются как прокси в профиле, но работают отдельными процессами.
Go-компилятор формирует конфиги, адаптер запускает процессы без shell.
Пути к бинарникам и сертификатам задаёт доверенный host. SOCKS слушает loopback;
занятый чужим процессом порт отклоняется до запуска. Linux/Android завершают
дочерние процессы при смерти host. Обычная, dev, CI-test и диагностическая
установки используют разные диапазоны портов и исключаются из VPN.

| Тип | Особенности |
|---|---|
| `naiveproxy` | HTTPS/QUIC, обязательная аутентификация, без UDP |
| `olcrtc` | Только клиент CNC, без UDP; `dns-server: system` берёт первый DNS Android |
| `byedpi` | Ручная стратегия либо автоматический подбор; UDP включён по умолчанию |
| `stormdns` | Настройки шифрования согласуются с сервером; без UDP |

Публичные поля и примеры — в [руководстве по узлам](../user-guide/profiles.md).
Версии, ABI и SHA-256 закреплены в `lib/product/runtime/*_release.dart`;
исходники и файлы зависимостей — рядом с
[ресурсами узлов](../../../../assets/runtimes/) и в
[tool/runtime_go_modules](../../../../tool/runtime_go_modules/README.md).
После обновления нужны пересборка ABI и проверка на реальном Android.

## Доступность и автоматические стратегии

Сначала проверяются процесс и локальный SOCKS-порт, затем HTTP(S)-запрос через
этот порт. Обязательная проверка входит в запуск: исчерпание `startup-timeout`
останавливает новые узлы и запускает откат. Необязательная идёт в фоне.
Прямого запасного запроса к тестовому адресу нет.

Подбор ByeDPI, повторы, кэш, сон и пробуждение принадлежат координатору.
Временные кандидаты используют разные порты; первый успешный отменяет остальные.
После foreground-бюджета запускается запасная стратегия, а поиск продолжается
в фоне. Подтверждённый результат применяется только к актуальному поколению.
Кэш стратегии разделён по физической сети; её смена отменяет прежний подбор.

StormDNS разворачивает источники резольверов в приватный `client_resolvers.txt`
с дедупликацией по IP. Смена системного DNS инвалидирует MTU-кэш. Новые файлы
фиксируются после успешного применения плана; откат возвращает прежние.
Лимиты адресов и сетевых запросов описаны в [безопасности](security.md).

## Снимок применённых правил Android VPN

`getAppliedAndroidVpnOptions` возвращает копию правил, переданных Builder при
последнем успешном создании VPN. `AccessControlService` сопоставляет их с
декларацией профиля. Пустой ответ означает, что подтверждённый снимок недоступен;
явные пустые `includePackage`/`excludePackage` сохраняют свой смысл.
Перезагрузка mihomo без пересоздания VPN не меняет этот снимок. UI различает
применённое состояние и декларацию профиля.

## Патчи mihomo

`tool/prepare_core.sh` пересоздаёт `core/vendor` из `go.mod`/`go.sum`, применяет
патчи без fuzz и запускает регрессионный тест Mieru. Сборка использует
`-mod=vendor`; общий Go module cache не меняется.

- `mihomo-mieru-terminal-timeout.patch` завершает чтение при таймауте закрытого
  QUIC-соединения, сохраняя обычный read deadline.
- `mihomo-embedded-command-gate.patch` передаёт изменяющие HTTP-команды backend.
- `mihomo-android-system-dns-lock.patch` синхронизирует доступ к системному DNS.

При обновлении зависимостей проверяются все патчи и их тесты. Исправленный
апстримом патч удаляется вместе с его вызовом в скрипте. Откат отдельного
исправления возвращает патч и вызов из соответствующей версии; `core/vendor`
после этого пересоздаётся. Пока нужны другие патчи, vendor-подготовка сохраняется.
