## 🔍 Проверка встроенных узлов

Запуск NaiveProxy, OlcRTC, ByeDPI и StormDNS проходит **два этапа**:

1. ✅ подтверждение живого процесса и локального SOCKS-порта;
2. 🌐 сквозной HTTP(S)-запрос строго через этот SOCKS-порт.

Product-слой проверяет и сериализует контракт из `lib/product/runtime/connectivity_check.dart`, а исполняет его Android-служба через `RuntimeNodeConnectivityChecker`.

**Транзакционность.** Обязательная проверка входит в транзакцию запуска: исчерпание `startup-timeout` останавливает новые узлы и запускает откат подготовленного плана. Необязательная проверка идёт в фоне и влияет только на журнал. Сохранённый манифест содержит тот же контракт, а платформенный слой Android выполняет его до быстрого запуска ядра при always-on восстановлении — поэтому **обычный и холодный запуск имеют одинаковые условия успеха**.

**Без прямого запасного соединения.** Имя разрешается до SOCKS-запроса, все полученные адреса должны быть публичными, а SOCKS-команда получает уже проверенный IP. TLS проверяет сертификат для исходного имени.

**Владение процессами.** Android-служба — единственный владелец как рабочих процессов, так и временных процессов подбора стратегии ByeDPI. Одиночный `probeRuntimeNode` сериализован с заменой рабочего плана; batch-вызов удерживает lock только при проверке snapshot и не блокирует смену плана во время сетевых запросов. Оба пути требуют обязательной безопасной проверки, всегда завершают временный процесс и не меняют действующий или сохранённый план. Неудачный кандидат отбрасывается; откат использует прежний кэш, а при его отсутствии — встроенную запасную стратегию. Обновление этого пути выполняется вместе для моста Dart, AIDL и Android-службы; возврат к предыдущей версии не требует переноса данных кэша.

**Автоподбор (batch).** Android-служба запускает ограниченное число кандидатов на разных loopback-портах, возвращает первый успешный и отменяет остальные. Один кандидат выполняет одну серию HTTP(S)-запросов без повторов и без удвоения таймаута. Dart ограничивает foreground-этап монотонным общим бюджетом; после него запускает fallback и продолжает список фоном. Успешный фоновый результат атомарно переводится в проверенный кэш, повторно применяет полный runtime plan и обновляет cold-start manifest. Смена плана отменяет продолжение по generation token, а Android всегда завершает уже запущенный batch.

## 🧩 Встроенные узлы

Встроенные узлы оформляются как обычные прокси в профиле. Жизненным циклом управляет `BuiltInProxySupervisor`.

> 📎 Пользовательская сторона (YAML, параметры) описана в [руководстве по встроенным узлам](../user-guide/profiles.md).

`BuiltInProxyCompiler` теперь только координирует работу: нормализует legacy-алиасы, выделяет локальные порты и передаёт канонический узел компилятору NaiveProxy, ByeDPI, OlcRTC или StormDNS. Каждый компилятор сам переводит публичные поля в нативный JSON, YAML или TOML.

### 🎭 naiveproxy

- **Тип:** `naiveproxy`
- **Обязательные поля:** `name`, `type`, `server`, `port`, `username`, `password`
- Разрешены только транспорты `https` и `quic`; анонимный доступ запрещён
- UDP не поддерживается; итоговый локальный узел `mihomo` получает `udp: false`
- Клиент сам выбирает локальный SOCKS5-адрес
- Компилятор экранирует учётные данные, собирает единственный внутренний URI и запускает NaiveProxy с автоматически созданным `config.json`
- Allowlist отклоняет `proxy`, `listen`, диагностические файлы, цепочки прокси и неизвестные поля

### 📞 olcrtc

- **Тип:** `olcrtc`
- **Обязательные поля:** `name`, `provider`, `room` (кроме `none`), `encryption-key`, `transport`, `dns-server` (`host:port` или `system`)
- Работает только в режиме CNC (клиент)
- UDP не поддерживается; итоговый локальный узел `mihomo` получает `udp: false`
- До запуска FlClashM проверяет правила provider/engine, параметры выбранного транспорта, ключ и DNS
- Android-сервис хранит ограниченный хвост вывода процесса; если OlcRTC завершился до открытия SOCKS5-порта, причина немедленно возвращается в Dart и показывается пользователю
- Запускается отдельным процессом через стабильный контракт `config.yaml`; мобильная библиотека не используется. При `dns-server: system` шаблон конфига отрисовывается платформой; pinned OlcRTC принимает один `net.dns`, поэтому используется первый системный DNS Android в формате `host:53` или `[IPv6]:53`
- Исходники закреплены на коммите `ad5758513335cda54362a64621c29e9d9fe759b4`
- `data: data` обязателен для CLI, но отдельная раскладка каталога не нужна: словари имён встроены в исполняемый файл, а отсутствующие внешние файлы считаются необязательным переопределением
- SHA-256 каждого двоичного файла закреплён рядом с коммитом; подготовка ресурсов и тесты отклоняют устаревшие или изменённые файлы даже при совпадающем штампе

### 🌩 stormdns

- **Тип:** `stormdns`
- **Обязательные поля:** `name`, `type`, `domains`, `encryption`, `encryption-key`
- Дефолтов у обязательных полей нет: согласования по протоколу StormDNS не выполняет, значения обязаны совпадать с сервером
- UDP не поддерживается; итоговый локальный узел `mihomo` получает `udp: false`
- Пресеты `messenger` / `balanced` / `bulk` задают дублирование и сжатие; порядок наложения — **дефолты StormDNS → preset → явные поля**
- Диапазоны схемы взяты из `finalizeClientConfig` StormDNS: всё, что upstream молча подрезает, отклоняется до запуска. Связанные границы проверяются целиком — `upload-setup` ≥ `upload`, `download-setup` ≥ `download`, `mtu.*.max` ≥ `min`, `nack-max-gap` ≤ `window/4`, `process-workers` ≥ `workers`, порядок RTO, ping-интервалов, ping-порогов и `session-retry-base` ≤ `session-retry-max`
- Объявляет строки-маркеры провала запуска; служба прерывает ожидание порта по совпадению, не досиживая бюджет в 120 с
- Исходники закреплены на коммите `87348df5b11f9e490262a713ca268734007af44f`
- SHA-256 каждого двоичного файла закреплён рядом с коммитом; подготовка ресурсов и тесты отклоняют устаревшие или изменённые файлы даже при совпадающем штампе

<details>
<summary>🔧 Обновление и откат stormdns</summary>

- **Обновление:** сменить закреплённый коммит, пересобрать три Android ABI закреплёнными Go 1.26.4 и NDK 28.0.13004108 командой `dart setup.dart android --out runtime-assets`, обновить закреплённые SHA-256 по полученным файлам и повторить команду и тесты.
- **Откат:** узел встроен впервые, предыдущего закреплённого коммита нет. Откат версии выполняется возвратом коммита и той же пересборкой; оперативный откат для пользователя — убрать узел из профиля. Миграция данных не требуется: рабочий кэш привязан к fingerprint и пересоздаётся.

</details>

**Генерируемый DNS-артефакт.** Android-контракт запуска расширен **обобщённо, без проверок типа ноды**: узел объявляет `resolverFile` с полями `template`, `path`, `dependsOnSystemDns`, `resetPaths` и режимом подстановки. Профиль размещает только шаблон, а читаемый процессом файл генерирует платформа — поэтому её перезапись никогда не выглядит как изменение профиля. `resolver-list` разворачивает все системные DNS для StormDNS; `single-host-port` подставляет ровно один маркер первым DNS как `host:53` или `[IPv6]:53` для OlcRTC. При смене системных DNS `RuntimeNodeResolverFile` атомарно перегенерирует файл, сбрасывает пути из `resetPaths` и перезапускает **только активные зависимые** узлы. Если новый процесс не поднялся, платформа атомарно возвращает предыдущий артефакт и пытается вернуть прежний процесс, оставляя новый DNS в очереди повторной попытки; независимые ноды не затрагиваются. `SystemDnsReader` читает системные DNS сам, потому что cold-start применяет план раньше установки `NetworkObserveModule`.

**Транзакционность нескольких артефактов.** `LocalNodeController` обслуживает несколько файлов на узел через stage → rollback → commit. Ревизия однофайловых узлов осталась байт-в-байт прежней, поэтому поведение NaiveProxy, OlcRTC и ByeDPI не изменилось. Рабочий кэш привязан к fingerprint итогового списка резольверов, `domains` и версии StormDNS; старый каталог удаляется только **после** успешного commit, а rollback возвращает состояние предыдущего плана.

**Сознательное отступление от upstream.** `usableHostCount` в StormDNS для IPv4 `/1` возвращает 2, а затем итерирует 2³¹−2 адреса. FlClashM считает фактический размер разворачивания и сверяет его с документированным лимитом 65536: CIDR из профиля, который в него не укладывается, отклоняется до запуска, а полученный по ссылке список усекается до лимита. Иначе такой профиль повесил бы приложение.

### 🛡 byedpi

- **Тип:** `byedpi`
- **Режим `manual`:** принимает строку `strategy`
- **Режим `auto`:** перебирает стратегии ByeByeDPI, кэширует рабочую
- Без `mode` наличие `strategy` выбирает ручной режим, а его отсутствие — автоматический
- `strategies` объединяет `builtin:byebyeedpi`, inline-стратегии и публичные HTTPS-списки; без него используется встроенный список
- Поддерживается подстановка `{sni}`
- UDP включён по умолчанию и передаётся локальному узлу `mihomo`; `udp: false` отключает его, а процесс ByeDPI не получает отдельного параметра UDP

### 😴 Активация `auto` (olcrtc и stormdns)

Supervisor заранее размещает артефакты спящего узла, но не включает его в live- или cold-start manifest, поэтому его обязательная сквозная проверка больше не входит в транзакцию запуска VPN. Watchdog проверяет наблюдаемую группу, пробуждает резерв после заданного числа ошибок, атомарно применяет полный plan и принудительно обновляет delay самого узла. После периода без соединений и выбора во всех прямых содержащих группах plan применяется без него, и процесс снова засыпает. Смена профиля и остановка отменяют переходы по generation token; состояние сна не сохраняется и после перезагрузки начинается заново.

Доступ к `mihomo` и состоянию сети изолирован интерфейсом `RuntimeHealthProbe`: product-слой видит только delay-тест, цепочки активных соединений, текущий `now` групп и наличие сети. Реализация — в app layer поверх `clashCore` и `connectivity_plus`. Без внедрённого probe автоматический watchdog бездействует, но staging, остановка и ручное пробуждение остаются безопасными. Режим `always` этот путь не использует и сохраняет прежнюю стартовую транзакцию.

Интеграция обновляется вместе с Dart-частью приложения и не меняет Android bridge; оперативный откат — `activation: always`, а откат версии не требует миграции состояния.

## 🚧 Ограничения

- Встроенные узлы работают только в секции `proxies`
- Локальные адреса и порты определяются клиентом
- ByeDPI в режиме `auto` проверяет URL из `strategy-test.urls` либо встроенный endpoint YouTube
- StormDNS медленный по своей природе: холодный запуск включает MTU-сканирование резольверов (на реальном устройстве — 28 с для трёх резольверов), поэтому `startup-timeout` по умолчанию поднят до 120 с

## 📸 Снимок применённых правил Android VPN

**Место в архитектуре.** `FlVpnService` сохраняет в `State.appliedOptions` неизменяемый снимок параметров **только после** успешного `VpnService.Builder.establish()` и отдаёт его через отдельный AIDL/MethodChannel-контракт `getAppliedAndroidVpnOptions`. `AccessControlService` сопоставляет снимок с декларацией текущего профиля; базовый экран получает только готовое состояние.

**Контракт и ограничения:**

- пустой ответ означает, что подтверждённый снимок недоступен;
- JSON с `includePackage: []` или `excludePackage: []` сохраняет явный режим с пустым списком и не равен отсутствию правила;
- снимок не обновляется при простой перезагрузке конфигурации ядра, потому что пакетные правила Android меняются только при пересоздании VPN;
- канал доступен только для чтения и не влияет на маршрутизацию;
- при недоступности снимка интерфейс явно сообщает, что показывает **декларацию профиля**, и не выдаёт её за применённое состояние.

**Обновление и откат.** Выполняется добавлением нового метода без изменения старого `getAndroidVpnOptions`, нужного для запуска VPN. Откат безопасен: старый путь запуска остаётся неизменным, а отсутствие нового ответа переводится в состояние «проверка недоступна».
