# Среда выполнения

## Цепочка обработки

```
RawProfile → ProfileCompiler → SecurityPolicy → RuntimePlan
```

После этого жизненным циклом управляют `EngineManager` и `EngineAdapter`.

## Встроенные узлы

Встроенные узлы оформляются как обычные прокси в профиле. Жизненным циклом управляет `BuiltInProxySupervisor`.

### naiveproxy

- **Тип:** `naiveproxy`
- **Обязательные поля:** `name`, `proxy`
- UDP не поддерживается; итоговый локальный узел Mihomo получает `udp: false`
- Клиент сам выбирает локальный SOCKS5-адрес
- Запускается с автоматически созданным `config.json`

### olcrtc

- **Тип:** `olcrtc`
- **Обязательные поля:** `name`, `auth.provider`, `room.id` (кроме `none`), `crypto.key`, `net.transport`, `net.dns`
- Работает только в режиме CNC (клиент)
- UDP не поддерживается; итоговый локальный узел Mihomo получает `udp: false`
- До запуска FlClashM проверяет обязательные поля, допустимые поставщики и транспорты, ключ, DNS и каждый итоговый запасной профиль
- Android-сервис хранит ограниченный хвост вывода процесса; если OlcRTC завершился до открытия SOCKS5-порта, причина немедленно возвращается в Dart и показывается пользователю
- Запускается отдельным процессом через стабильный контракт `config.yaml`; мобильная библиотека не используется
- Исходники закреплены на коммите `ad5758513335cda54362a64621c29e9d9fe759b4`
- `data: data` обязателен для CLI, но отдельная раскладка каталога не нужна: словари имён встроены в исполняемый файл, а отсутствующие внешние файлы считаются необязательным переопределением
- SHA-256 каждого двоичного файла закреплён рядом с коммитом; подготовка ресурсов и тесты отклоняют устаревшие или изменённые файлы даже при совпадающем штампе
- Обновление: сменить закреплённый коммит, пересобрать три Android ABI закреплёнными Go 1.26.4 и NDK 28.0.13004108 командой `dart setup.dart android --out runtime-assets`, обновить закреплённые SHA-256 по полученным файлам и повторить команду и тесты
- Откат: вернуть предыдущий коммит `5dd6822d807e3352fe4452a3b071e043d958a020` и той же командой пересобрать артефакты

### byedpi

- **Тип:** `byedpi`
- **Режим `manual`:** принимает строку `args`
- **Режим `auto`:** перебирает стратегии ByeByeDPI, кэширует рабочую
- Поддерживается подстановка `{sni}`
- UDP включён по умолчанию и передаётся локальному узлу Mihomo; `udp: false`
  отключает его, а процесс ByeDPI не получает отдельного параметра UDP

## Ограничения

- Встроенные узлы работают только в секции `proxies`
- Локальные адреса и порты определяются клиентом
- ByeDPI в режиме `auto` проверяет только URL из `test.urls`

## Снимок применённых правил Android VPN

Место в архитектуре: `FlVpnService` сохраняет в `State.appliedOptions` неизменяемый
снимок параметров только после успешного `VpnService.Builder.establish()` и
передаёт его на чтение через отдельный AIDL/MethodChannel-контракт
`getAppliedAndroidVpnOptions`. `AccessControlService` сопоставляет снимок с
декларацией текущего профиля; базовый экран получает только готовое состояние.

Контракт и ограничения:

- пустой ответ означает, что подтверждённый снимок недоступен;
- JSON с `includePackage: []` или `excludePackage: []` сохраняет явный режим с
  пустым списком и не равен отсутствию правила;
- снимок не обновляется при простой перезагрузке конфигурации ядра, потому что
  пакетные правила Android меняются только при пересоздании VPN;
- канал доступен только для чтения и не влияет на маршрутизацию;
- при недоступности снимка интерфейс явно сообщает, что показывает декларацию
  профиля, и не выдаёт её за применённое состояние.

Обновление выполняется добавлением нового метода без изменения старого
`getAndroidVpnOptions`, нужного для запуска VPN. Откат безопасен: старый путь
запуска остаётся неизменным, а отсутствие нового ответа переводится в состояние
«проверка недоступна».
