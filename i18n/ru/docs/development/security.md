# Политика безопасности

## Базовый принцип

Политика безопасности определяется клиентом, а не провайдером.

**Провайдер может:**
- передавать метаданные;
- подсказки оформления;
- рекомендательные настройки.

**Провайдер не может:**
- ослаблять защиты клиента;
- задавать обязательное поведение через заголовки.

## Защиты Android

- TUN принудительно включается
- Раздельное туннелирование из профиля имеет приоритет
- Индикатор применённых пакетных правил читает снимок Android VPN-службы, а не
  текущую конфигурацию ядра
- Каталог обновлений приложения проверяется встроенным открытым ключом Ed25519
  до разбора содержимого.
- Загрузчик обновлений проверяет SHA-256 APK из подписанного каталога и
  перебирает только перечисленные в нём зеркала.
- Подпись APK дополнительно проверяется установщиком Android относительно
  подписи уже установленного приложения.
- Встроенные узлы не могут задавать локальные адреса и порты
- `olcrtc` работает только в режиме CNC
- В `olcrtc profiles[]` рекурсивно запрещены `socks.host`, `socks.port` и `crypto.key_file`; остальные поля прозрачно передаются OlcRTC
- `byedpi` проверяет только указанные URL

## Адреса проверки доступности

Для `connectivity-check` и `strategy-test` разрешены только HTTP(S)-адреса без учётных данных и локальных назначений. Запрещены петлевые, частные, канальные, многоадресные и служебные диапазоны, а также локальные имена. Перед сетевым запросом результат DNS проверяется повторно; соединение к назначению устанавливается только командой SOCKS через проверяемый встроенный узел.

## Заголовки провайдера

- Заголовки `flclashm-*` остаются рекомендательными
- Оформление не может менять защиты среды выполнения
