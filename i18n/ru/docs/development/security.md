# Политика безопасности

Security-critical решения runtime и обновления приложения принимаются локальным
кодом и подписанными артефактами. HTTP-заголовки провайдера, текст профиля и
доступность зеркала не могут ослабить обязательные защиты этих путей.

## Границы доверия

| Вход | Уровень доверия | Что разрешено |
| --- | --- | --- |
| YAML-профиль | Недоверенный | Маршрутизация и поля из строгой схемы; локальные runtime-адреса назначает клиент |
| Provider headers | В основном рекомендательный | Текст, оформление и opt-in настройки; отдельно разрешены interval и миграция hostname подписки |
| Каталог обновлений | Доверенный после Ed25519 | Версия, SHA-256 и упорядоченные зеркала APK |
| APK | Доверенный после SHA-256 и Android signature continuity | Установка поверх текущего приложения |
| Runtime binaries | Доверенные артефакты репозитория | Запуск Android service после проверки закреплённых release metadata и digest |

## Профиль и runtime

- `SecurityPolicy` принудительно включает TUN на Android.
- NaiveProxy, OlcRTC и ByeDPI проходят строгую allowlist-схему. Неизвестные и
  запрещённые поля отклоняются до запуска.
- Локальные SOCKS-адреса и порты назначает FlClashM. Профиль не может подменить
  `listen` или направить внутренний мост на произвольный локальный сервис.
- OlcRTC работает только как CNC-клиент. В запасных `profiles[]` рекурсивно
  запрещены `socks.host`, `socks.port` и `crypto.key_file`.
- NaiveProxy требует аутентификацию; диагностические файлы и цепочки upstream
  proxy не входят в разрешённую схему.
- CLI ByeDPI разбирается собственным валидатором; неизвестные и опасные
  аргументы не передаются процессу вслепую.

## Сетевые проверки

`connectivity-check`, `strategy-test` и wake-проверки принимают только публичные
HTTP(S)-URL без userinfo и fragment. Запрещены loopback, private, link-local,
multicast и служебные диапазоны, а также локальные имена.

DNS выполняется до SOCKS-команды, и каждый полученный адрес проверяется заново.
Сам HTTP(S)-запрос идёт строго через проверяемый узел к уже проверенному IP; TLS
при этом сверяет сертификат исходного hostname. Прямого fallback-запроса в обход
узла нет. Любой HTTP status доказывает транспортную связность, поэтому `4xx` и
`5xx` считаются успешным ответом проверки.

## Android VPN и пакетные правила

Профильный split tunneling имеет приоритет над ручным списком. После успешного
`VpnService.Builder.establish()` Android service сохраняет неизменяемый снимок
применённых package rules. UI читает этот снимок через отдельный read-only
контракт и явно сообщает, если доступна только декларация профиля.

Снимок не обновляется при простой перезагрузке конфигурации `mihomo`: изменение
списка Android-приложений требует пересоздания VPN. Пустой include/exclude list —
явный применённый режим, а не отсутствие правила.

## Обновление приложения

SourceForge публикует `stable.json` и `pre.json` с отдельными бинарными
подписями. Клиент проверяет Ed25519 до разбора JSON, затем сверяет канал,
монотонные `versionCode` и время публикации, выбирает ABI и проверяет SHA-256
APK. Зеркала берутся только из подписанного каталога.

Финальную непрерывность подписи обеспечивает Android: APK с другим сертификатом
не может обновить установленный `com.makriq.flclash`. Откат каталога и downgrade
версии запрещены; исправление выпускается новым тегом с большим `versionCode`.

## Provider advisory и секреты

Заголовки `flclashm-*`, `announce` и `support-url` не меняют TUN, runtime-схему,
URL сетевых проверок, доверенные ключи или правила обновления приложения. Часть
подсказок применяется только при явном `flclashm-custom`, а пользователь может
запретить переопределение настроек.

Отдельный `flclashm-newdomain` меняет hostname сохранённой подписки после
успешного ответа текущего провайдера. Это ограниченная операция control plane,
а не runtime advisory: новый домен получит последующие запросы профиля и device
headers. Провайдеру следует использовать только HTTPS-домен под тем же
операционным контролем.

Профили и логи могут содержать URL подписки, пароли NaiveProxy, ключ OlcRTC и
токены. Шаблон issue требует очищать их; автоматической гарантии редактирования
всех пользовательских вложений нет.
