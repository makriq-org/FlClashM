# Подсказки провайдера

При добавлении или обновлении URL-профиля FlClashM сохраняет часть HTTP-заголовков
как provider metadata. Большинство полей меняет отображение и предлагает
пользовательские настройки; два операционных поля управляют интервалом и адресом
следующего refresh. Заголовки не влияют на TUN, строгую схему runtime, сетевые
проверки встроенных узлов или доверие к обновлениям приложения.

Имена заголовков приводятся к нижнему регистру. Неизвестные подсказки
игнорируются.

## Запрос подписки и refresh

По умолчанию URL-профиль отправляет провайдеру `x-hwid`, `x-device-os`,
`x-ver-os` и `x-device-model`, если значения доступны на устройстве. Оператор
должен считать их пользовательскими данными, хранить минимально необходимое
время и не требовать публикации этих значений в issue.

| Заголовок ответа | Назначение |
| --- | --- |
| `profile-update-interval` | Положительное целое число часов между автоматическими обновлениями |
| `flclashm-newdomain` | Заменяет hostname сохранённого URL подписки для следующих refresh |

`flclashm-newdomain` принимается только из успешного ответа текущего провайдера,
но новый hostname затем получает профильные запросы и device headers. Используйте
поле только для осознанной миграции на доверенный HTTPS-домен; оно не является
обычной визуальной подсказкой.

## Информация и поддержка

| Заголовок | Формат | Назначение |
| --- | --- | --- |
| `announce` | Base64 или `base64:<payload>`; обычный текст остаётся fallback | Объявление профиля |
| `support-url` | URL | Ссылка поддержки в карточке/уведомлении профиля |
| `flclashm-servicename` | Base64 UTF-8 или обычный текст | Название сервиса |
| `flclashm-servicelogo` | Base64 UTF-8 или обычный текст | URL логотипа |
| `flclashm-serverinfo` | Base64 UTF-8 или обычный текст | Имя группы с серверной информацией |
| `x-hwid-max-devices-reached` | `true` | Уведомление о достигнутом лимите устройств |
| `x-hwid-not-supported` | `true` | Уведомление об отсутствии поддержки HWID |

Если при очередном refresh отсутствуют `announce`, `support-url` или HWID flags,
их старые значения удаляются. Остальные сохранённые настройки не стираются
отсутствующим заголовком автоматически.

## Отображение

| Заголовок | Формат | Назначение |
| --- | --- | --- |
| `flclashm-background` | URL | Фоновое изображение профиля |
| `flclashm-globalmode` | `false` отключает | Видимость отдельной GLOBAL-группы |
| `flclashm-newboard` | `true` | Новый dashboard, если пользователь не сделал явный выбор |
| `flclashm-denywidgets` | `true` | Блокировка редактирования dashboard |

Эти значения читаются как display hints и не требуют
`flclashm-custom`. Пользовательское явное значение dashboard имеет приоритет над
рекомендацией `flclashm-newboard`.

## Настройки, применяемые по триггеру

`flclashm-custom` определяет момент применения:

- `add` — только при первом добавлении профиля;
- `update` — при добавлении и каждом обновлении;
- любое другое значение — не применять patch настроек.

При активном триггере доступны:

| Заголовок | Формат |
| --- | --- |
| `flclashm-settings` | CSV: `minimize`, `autorun`, `shadowstart`, `autostart`, `autoupdate` |
| `flclashm-hex` | `RRGGBB[:variant][:pureblack]` или `AARRGGBB...` |
| `flclashm-widgets` | Список widget-id в формате dashboard parser |
| `flclashm-view` | `key:value` через `;`: `type`, `sort`, `layout`, `icon`, `card` |

Пример настройки страницы прокси:

```text
flclashm-custom: add
flclashm-view: type:list;sort:delay;layout:tight;icon:none;card:min
flclashm-hex: 6750A4:tonalSpot:pureblack
flclashm-settings: autostart,autoupdate
```

Допустимые значения `flclashm-view`:

- `type`: `list`, `tab`;
- `sort`: `none`, `delay`, `name`;
- `layout`: `loose`, `standard`, `tight`;
- `icon`: `icon`, `standard`, `none`;
- `card`: `expand`, `shrink`, `min`, `oneline`.

Некорректные части подсказки пропускаются. Если пользователь включил
переопределение provider settings, `flclashm-settings` не меняет его настройки;
визуальные patch-подсказки обрабатываются отдельно.

## Границы безопасности

Provider metadata не может:

- отключить Android TUN или изменить фактически применяемые package rules;
- добавить разрешённое поле встроенного узла или CLI-аргумент ByeDPI;
- заменить connectivity URL после профильной валидации;
- изменить ключ Ed25519, SHA-256, список доверенных зеркал или Android-подпись;
- запускать произвольный код.

`flclashm-settings` может рекомендовать автозапуск и автоматическую проверку
обновлений только в рамках пользовательских настроек. Security-critical
поведение runtime и апдейтера остаётся в локальной policy. Исключение по области
действия — описанная выше миграция URL подписки через `flclashm-newdomain`; она
не меняет runtime plan, но меняет адрес будущего получения профиля.
