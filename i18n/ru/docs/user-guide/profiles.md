# Встроенные узлы

Встроенные узлы задаются прямо в YAML-профиле и работают как обычные прокси. FlClashM сам запускает нужные процессы и управляет портами.

## Проверка запуска

Для NaiveProxy, OlcRTC и ByeDPI всегда проверяются процесс и локальный SOCKS-порт. После этого можно настроить сквозной запрос, который выполняется только через этот SOCKS-порт:

```yaml
connectivity-check:
  urls:
    - "https://example.org/generate_204"
  required: true
  timeout: 5
  startup-timeout: 30
  retry-interval: 1
  requests: 1
  concurrency: 1
  min-success-ratio: 1.0
```

Все поля необязательны. Значения по умолчанию: `required: false`, `timeout: 5`, `startup-timeout: 30`, `retry-interval: 1`, `requests: 1`, `concurrency: 1`. Без `min-success-ratio` достаточно одного успешного ответа. Адрес выбирается в порядке: `connectivity-check.urls` узла, адрес ближайшей содержащей группы, общий адрес проверки приложения. Если адреса нет, остаются проверки процесса и порта.

При `required: false` сквозная проверка не задерживает запуск и только пишет ошибку в журнал. При `required: true` отсутствие адреса отклоняет профиль, а неудача отменяет запуск с откатом. Любой корректный ответ HTTP, в том числе `4xx` и `5xx`, считается успешным. Допустимы только публичные HTTP(S)-адреса без учётных данных и фрагментов.

## ByeDPI

**Тип:** `byedpi`

UDP включён по умолчанию. Чтобы отключить его для узла, укажите `udp: false`.

Поддерживает два режима:

### Автоматический подбор стратегии

Клиент перебирает стратегии из списка ByeByeDPI, находит рабочую и кэширует её.

```yaml
proxies:
  - name: "dpi-auto"
    type: byedpi
```

**Параметры:**

| Параметр | Описание |
|----------|----------|
| `strategy-list` | Имя списка стратегий; по умолчанию `byebyeedpi` |
| `strategies` | Собственный упорядоченный список аргументов вместо `strategy-list` |
| `strategy-test.urls` | Адреса для подбора; по умолчанию используется встроенный тестовый endpoint YouTube |
| `strategy-test.sni` | Имя хоста для подстановки `{sni}` |
| `strategy-test.timeout` | Таймаут одной проверки в секундах (по умолчанию 5) |
| `strategy-test.requests` | Количество запросов на стратегию (по умолчанию 1) |
| `strategy-test.concurrency` | Параллельных HTTP-запросов внутри одного кандидата (по умолчанию 4) |
| `strategy-test.min-success-ratio` | Минимальная доля успешных запросов (по умолчанию 1.0) |
| `selection.concurrency` | Одновременно проверяемых стратегий (по умолчанию 4) |
| `selection.foreground-timeout` | Общий бюджет подбора до запуска узла, в секундах (по умолчанию 15) |
| `selection.background` | Продолжать оставшийся список после запуска fallback (по умолчанию `true`) |
| `fallback-args` | Аргументы временной стратегии, если foreground-подбор не успел завершиться |
| `cache.ttl` | Время жизни кэша в секундах (по умолчанию 7 дней) |
| `cache.recheck-after` | Интервал повторной проверки в секундах (по умолчанию 1 день) |
| `cache.retry-after` | Пауза перед новым foreground-подбором после временного fallback (по умолчанию 5 минут) |
| `cache.failure-threshold` | Количество ошибок до сброса кэша (по умолчанию 2) |

Кандидаты проверяются параллельно ограниченными группами. Если за foreground-бюджет
ничего не найдено, узел сразу запускается с fallback, а оставшийся список
проверяется в фоне. Найденная стратегия переключается в рабочий план и
сохраняется для холодного запуска.

Если `mode` не указан, узел с `args` работает в ручном режиме, а без `args` — в автоматическом. `strategy-test` используется только при автоподборе и переопределяет встроенный тестовый endpoint, не заменяя `connectivity-check`. Старая секция `test` запрещена; её нужно переименовать в `strategy-test`.

Любой корректный HTTP-ответ сервера, включая `4xx` и `5xx`, считается успешной
проверкой. Проверенный результат и временный fallback хранятся в кэше раздельно:
fallback не блокирует последующие попытки подбора на время обычного TTL.

### Ручная стратегия

```yaml
proxies:
  - name: "dpi-fixed"
    type: byedpi
    mode: manual
    args: "--disorder 1 --auto=torst --tlsrec 1+s"
```

## OlcRTC

**Тип:** `olcrtc`

UDP не поддерживается; допустимо только `udp: false`.

```yaml
proxies:
  - name: "rtc"
    type: olcrtc
    auth:
      provider: jitsi
    room:
      id: "https://meet.example.org/room"
    crypto:
      key: "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    net:
      transport: datachannel
      dns: "1.1.1.1:53"
```

**Параметры:**

| Параметр | Описание |
|----------|----------|
| `auth.provider` | Поставщик соединения (`jitsi`, `telemost`, `wbstream`, `none`) |
| `room.id` | Идентификатор комнаты видеозвонка |
| `crypto.key` | 256-битный ключ шифрования: ровно 64 шестнадцатеричных знака |
| `net.transport` | Транспорт (`datachannel`, `vp8channel`, `seichannel`, `videochannel`) |
| `net.dns` | Обязательный DNS-сервер в виде `адрес:порт` |

Для `wbstream` рекомендуется `vp8channel`: гостевой режим этого поставщика не
даёт права на публикацию канала данных. Параметры `vp8.fps` и
`vp8.batch_size` необязательны; OlcRTC подставляет значения `30` и `64`.

Если заданы `profiles`, общие поля верхнего уровня наследуются каждым запасным
профилем. FlClashM проверяет итоговую конфигурацию каждого профиля до запуска.
Локальный адрес, порт SOCKS5, режим CNC и каталог данных назначает клиент —
указывать или переопределять их в профиле нельзя.

Ошибки обязательных полей показываются при проверке профиля. Если процесс
OlcRTC завершится позднее, клиент выводит код завершения и последние строки
сообщения процесса вместо ожидания тайм-аута порта.

## NaiveProxy

**Тип:** `naiveproxy`

UDP не поддерживается; допустимо только `udp: false`.

```yaml
proxies:
  - name: "naive"
    type: naiveproxy
    server: example.com
    port: 443
    username: user
    password: pass
```

Обязательные поля: `name`, `type`, `server`, `port`, `username`, `password`.
`transport` по умолчанию равен `https`; также разрешён `quic`. Дополнительно
можно задать `insecure-concurrency` (1–4), `tunnel-timeout`, `idle-timeout`,
`post-quantum`, карту `headers`, `host-resolver-rules` и общий
`connectivity-check`.

Клиент безопасно собирает URI с экранированными учётными данными, передаёт его
NaiveProxy и подменяет узел для Mihomo на локальный SOCKS5. Старое поле `proxy`
не поддерживается. `listen`, диагностические файлы, цепочки прокси и любые
неизвестные поля отклоняются при проверке профиля.

## Ограничения

- Встроенные узлы задаются только в секции `proxies`.
- Клиент сам управляет локальными адресами и портами.
- Профиль не может задавать локальный `listen`; `server` и `port` у NaiveProxy
  описывают только удалённый сервер.
- ByeDPI использует UDP по умолчанию, но позволяет отключить его через
  `udp: false`. NaiveProxy и OlcRTC UDP не поддерживают.
