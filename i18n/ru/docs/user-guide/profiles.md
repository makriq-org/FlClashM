# 🧩 Встроенные узлы

Главная суперсила FlClashM: **специальные узлы описываются прямо в YAML-профиле** и ведут себя как обычные прокси. Клиент сам запускает нужные процессы, выдаёт им локальные порты и подставляет в маршрутизацию `mihomo`. В правилах их можно смешивать как угодно — один сайт через `byedpi`, другой через `olcrtc`, остальное напрямую.

Поддерживаются три типа:

| Тип | Что делает | Когда пригодится |
|-----|-----------|------------------|
| 🛡 [`byedpi`](#-byedpi) | Обход DPI манипуляцией пакетами | Ресурсы, заблокированные «изнутри»: YouTube, Discord и т. п. |
| 📞 [`olcrtc`](#-olcrtc) | Туннель поверх WebRTC под видом видеозвонка | Обход белых списков (например, через Yandex Telemost / Jitsi) |
| 🎭 [`naiveproxy`](#-naiveproxy) | Маскировка под трафик Chrome | Обход чёрных списков, устойчивость к TLS-fingerprint |

> ℹ️ Встроенные узлы задаются **только** в секции `proxies`. Локальные адреса и порты назначает клиент — задавать их в профиле нельзя.

---

## 🔍 Проверка запуска

Прежде чем считать узел готовым, FlClashM всегда проверяет две вещи: **живой процесс** и **открытый локальный SOCKS-порт**. Это работает для NaiveProxy, OlcRTC и ByeDPI.

Поверх этого можно включить **сквозную проверку** — реальный HTTP(S)-запрос, который идёт строго через SOCKS-порт узла:

```yaml
connectivity-check:
  urls:
    - "https://example.org/generate_204"
  required: true
  timeout: 5
  startup-timeout: 30
  retry-interval: 1
  requests: 1
  concurrency: 1
  min-success-ratio: 1.0
```

| Поле | По умолчанию | Что задаёт |
|------|--------------|-----------|
| `urls` | — | Адреса для проверки (публичные HTTP(S), без учётных данных и фрагментов) |
| `required` | `false` | Обязательна ли проверка для запуска |
| `timeout` | `5` | Таймаут одного запроса, секунды |
| `startup-timeout` | `30` | Общий бюджет проверки при запуске, секунды |
| `retry-interval` | `1` | Пауза между попытками, секунды |
| `requests` | `1` | Сколько запросов сделать |
| `concurrency` | `1` | Сколько запросов параллельно |
| `min-success-ratio` | — | Минимальная доля успешных ответов (без неё достаточно одного) |

**Как выбирается адрес.** По порядку: `connectivity-check.urls` самого узла → адрес ближайшей содержащей группы → общий адрес проверки приложения. Если адреса нет, остаются только проверки процесса и порта.

> ⚠️ **Разница между `required: false` и `required: true`:**
> - `false` — проверка идёт в фоне, не задерживает запуск, при неудаче лишь пишет в журнал.
> - `true` — отсутствие адреса **отклоняет** профиль, а неудачная проверка **отменяет** запуск с откатом подготовленного плана.
>
> Успешным считается **любой** корректный HTTP-ответ, включая `4xx` и `5xx`. Допустимы только публичные HTTP(S)-адреса без учётных данных и фрагментов.

## 🛡 ByeDPI

**Тип:** `byedpi` · UDP включён по умолчанию (отключить — `udp: false`)

ByeDPI обходит DPI, «портя» пакеты так, чтобы фильтр не смог распознать соединение. У узла два режима.

### 🤖 Автоматический подбор стратегии

Клиент перебирает стратегии из списка ByeByeDPI, находит рабочую и кэширует её — на холодный старт она подхватывается сразу.

```yaml
proxies:
  - name: "dpi-auto"
    type: byedpi
```

Как это работает: кандидаты проверяются параллельно небольшими группами. Если за отведённый бюджет ничего не нашлось — узел стартует с временной (fallback) стратегией, а остаток списка проверяется в фоне. Найденная рабочая стратегия атомарно переключается в план и сохраняется.

<details>
<summary>⚙️ Все параметры авто-режима</summary>

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `strategy-list` | `byebyeedpi` | Имя списка стратегий |
| `strategies` | — | Свой упорядоченный список аргументов вместо `strategy-list` |
| `strategy-test.urls` | встроенный endpoint YouTube | Адреса для подбора |
| `strategy-test.sni` | — | Имя хоста для подстановки `{sni}` |
| `strategy-test.timeout` | `5` | Таймаут одной проверки, секунды |
| `strategy-test.requests` | `1` | Запросов на стратегию |
| `strategy-test.concurrency` | `4` | Параллельных HTTP-запросов внутри кандидата |
| `strategy-test.min-success-ratio` | `1.0` | Минимальная доля успешных запросов |
| `selection.concurrency` | `4` | Одновременно проверяемых стратегий |
| `selection.foreground-timeout` | `15` | Бюджет подбора до запуска узла, секунды |
| `selection.background` | `true` | Продолжать список в фоне после fallback |
| `fallback-args` | — | Аргументы временной стратегии, если foreground не успел |
| `cache.ttl` | 7 дней | Время жизни кэша, секунды |
| `cache.recheck-after` | 1 день | Интервал повторной проверки, секунды |
| `cache.retry-after` | 5 минут | Пауза перед новым подбором после fallback, секунды |
| `cache.failure-threshold` | `2` | Число ошибок до сброса кэша |

</details>

> ℹ️ `strategy-test` используется **только** при автоподборе и переопределяет встроенный тестовый endpoint — он не заменяет `connectivity-check`. Проверенный результат и временный fallback хранятся в кэше **раздельно**: fallback не блокирует последующие попытки подбора на время обычного TTL. Успешной считается любая HTTP-проверка, включая `4xx` и `5xx`.
>
> 🚫 Старая секция `test` больше не поддерживается — переименуйте её в `strategy-test`.

### ✍️ Ручная стратегия

```yaml
proxies:
  - name: "dpi-fixed"
    type: byedpi
    mode: manual
    args: "--disorder 1 --auto=torst --tlsrec 1+s"
```

> 💡 Если `mode` не указан: наличие `args` включает **ручной** режим, а их отсутствие — **автоматический**.

## 📞 OlcRTC

**Тип:** `olcrtc` · UDP не поддерживается (допустимо только `udp: false`)

OlcRTC заворачивает трафик в WebRTC и выдаёт его за обычный видеозвонок через разрешённый сервис — так соединение проходит сквозь белые списки.

```yaml
proxies:
  - name: "rtc"
    type: olcrtc
    auth:
      provider: jitsi
    room:
      id: "https://meet.example.org/room"
    crypto:
      key: "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    net:
      transport: datachannel
      dns: "1.1.1.1:53"
proxy-groups:
  - name: "main"
    type: fallback
    url: "https://example.org/generate_204"
    proxies: ["DIRECT", "rtc"]
```

| Параметр | Описание |
|----------|----------|
| `auth.provider` | Поставщик соединения: `jitsi`, `telemost`, `wbstream`, `none` |
| `room.id` | Идентификатор комнаты видеозвонка |
| `crypto.key` | 256-битный ключ шифрования — **ровно 64 hex-символа** |
| `net.transport` | Транспорт: `datachannel`, `vp8channel`, `seichannel`, `videochannel` |
| `net.dns` | Обязательный DNS-сервер в формате `адрес:порт` |

### 😴 Активация (спящий резерв)

По умолчанию OlcRTC работает как **запасной узел**: конфигурация готова заранее, но процесс спит, пока основная группа не начнёт падать или пользователь не выберет OlcRTC вручную.

```yaml
activation: auto
# activation: always  # прежний режим: запускать вместе с VPN
```

Полная форма даёт контроль над пробуждением и засыпанием:

```yaml
activation:
  mode: auto
  wake:
    urls: ["https://example.org/generate_204"]
    interval: 30
    failures: 2
    retry-after: 300
  sleep:
    idle: 900
```

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `mode` | `auto` | `auto` усыпляет резерв; `always` — прежний постоянный запуск |
| `wake.urls` | цепочка `connectivity-check` | Публичные HTTP(S)-адреса для проверки наблюдаемой группы |
| `wake.interval` | `30` | Интервал проверки во сне, секунды |
| `wake.failures` | `2` | Неудачных раундов подряд до пробуждения |
| `wake.retry-after` | `300` | Пауза после неудачного запуска, секунды |
| `sleep.idle` | `900` | Время без соединений и выбора до сна; `0` — не засыпать до перезапуска VPN |

**Что важно знать про `auto`:**
- Узел должен напрямую входить хотя бы в одну proxy group.
- Адреса проверки должны разрешаться из `wake.urls`, `connectivity-check` узла, ближайшей группы или глобального тестового URL приложения.
- После пробуждения клиент сразу проверяет сам OlcRTC. Если ни одна содержащая группа его не выбрала и активных соединений нет в течение `sleep.idle` — процесс снова засыпает.
- **Ручной выбор пробуждает узел немедленно.**

> ℹ️ Режим `auto` используется теперь **даже без поля `activation`**. Чтобы полностью вернуть прежнее поведение, явно укажите `activation: always`.

> 💡 Для `wbstream` рекомендуется `vp8channel`: гостевой режим этого поставщика не даёт права публиковать канал данных. Необязательные `vp8.fps` и `vp8.batch_size` по умолчанию `30` и `64`.

Если заданы `profiles`, общие поля верхнего уровня наследуются каждым запасным профилем, и FlClashM проверяет итоговую конфигурацию каждого из них до запуска. Локальный адрес, порт SOCKS5, режим CNC и каталог данных назначает клиент — переопределять их в профиле нельзя.

> ⚠️ Ошибки обязательных полей видны уже при проверке профиля. Если процесс OlcRTC упадёт позже, клиент покажет **код завершения и последние строки вывода** вместо ожидания тайм-аута порта.

## 🎭 NaiveProxy

**Тип:** `naiveproxy` · UDP не поддерживается (допустимо только `udp: false`)

NaiveProxy маскирует трафик под обычные запросы Chrome, используя сетевой стек Chromium — это устойчиво к TLS-fingerprint и активному зондированию.

```yaml
proxies:
  - name: "naive"
    type: naiveproxy
    server: example.com
    port: 443
    username: user
    password: pass
```

- **Обязательные поля:** `name`, `type`, `server`, `port`, `username`, `password`.
- `transport` по умолчанию `https`; также разрешён `quic`.
- Дополнительно: `insecure-concurrency` (1–4), `tunnel-timeout`, `idle-timeout`, `post-quantum`, карта `headers`, `host-resolver-rules` и общий `connectivity-check`.

Клиент безопасно собирает URI с экранированными учётными данными, передаёт его NaiveProxy и подменяет узел для `mihomo` на локальный SOCKS5.

> 🚫 Старое поле `proxy` не поддерживается. `listen`, диагностические файлы, цепочки прокси и любые неизвестные поля **отклоняются** при проверке профиля.

---

## 🚧 Ограничения

- Встроенные узлы задаются только в секции `proxies`.
- Клиент сам управляет локальными адресами и портами.
- Профиль не может задавать локальный `listen`; у NaiveProxy `server` и `port` описывают только удалённый сервер.
- UDP: `byedpi` — включён (можно отключить `udp: false`); `naiveproxy` и `olcrtc` UDP **не поддерживают**.
