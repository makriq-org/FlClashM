# Раздельное туннелирование Android-приложений

FlClashM может включать в VPN только выбранные приложения или исключать их. Если
правила объявлены в YAML-профиле, они имеют приоритет над ручным списком в UI.

## Два взаимоисключающих режима

Только выбранные приложения используют VPN:

```yaml
tun:
  enable: true
  include-package:
    - org.telegram.messenger
    - com.termux
```

Все приложения используют VPN, кроме выбранных:

```yaml
tun:
  enable: true
  exclude-package:
    - com.android.chrome
    - org.mozilla.firefox
```

Источники include и exclude нельзя смешивать. Ограничение относится ко всем
полям одного режима: например, `include-package` вместе с
`exclude-package-url` тоже считается неоднозначной конфигурацией и отклоняется.

## Селекторы приложений

| Формат | Пример | Результат |
| --- | --- | --- |
| Точное имя | `com.termux` | Совпадает с одним Android package name |
| Glob | `*.yandex.*` | `*` заменяет любое число символов |
| RegExp | `re:^org\.mozilla\..+$` | Dart-совместимое регулярное выражение |
| RegExp, полная форма | `regex:^org\.mozilla\.` | Также принимаются префиксы `regex:` и `regexp:` |
| Исключение из результата | `!ru.yandex.browser` | Удаляет совпадения, добавленные предыдущими селекторами |

Порядок важен: отрицательный селектор удаляет пакеты из уже собранного набора.
Glob и RegExp разворачиваются по списку установленных приложений. Точный inline
package name может быть сохранён даже когда inventory недоступен; селекторы из
внешнего списка без inventory не применяются вслепую.

```yaml
tun:
  enable: true
  exclude-package:
    - '*.yandex.*'
    - '!ru.yandex.browser'
    - 're:^org\.mozilla\..+$'
```

## Локальные списки

`include-package-file` и `exclude-package-file` принимают путь, descriptor или
список источников:

```yaml
tun:
  enable: true
  include-package-file:
    - lists/messengers.txt
    - path: lists/work.yaml
```

Относительный путь считается от каталога профилей. Абсолютный путь и symlink
тоже должны оставаться внутри этого каталога; выход через `..` отклоняется.

Файл может быть YAML-списком или текстом по одному селектору на строку. Пустые
строки и строки с `#` игнорируются; поддерживается inline-комментарий после
пробела и `#`.

## Удалённые списки и кэш

```yaml
tun:
  enable: true
  include-package-url:
    - https://example.com/android-packages.txt
    - url: https://example.org/work.yaml
      path: providers/work-packages.yaml
```

Поля `*-package-url` принимают только HTTP(S). При первом чтении список
загружается и валидируется до записи кэша. При следующих подключениях уже
проверенный кэш применяется сразу, а обновление идёт в фоне. Ошибка фонового
обновления не повреждает предыдущий файл. Если кэша ещё нет и URL недоступен,
компиляция профиля завершается ошибкой.

Descriptor с `url` и `path` задаёт собственный путь кэша, который также обязан
оставаться в каталоге профилей. Без `path` клиент создаёт внутренний путь по
идентификатору профиля и hash URL.

## Применение и отображение

Компилятор разворачивает все селекторы в точные package name, удаляет служебные
поля `*-file`/`*-url` из конфигурации `mihomo` и передаёт результат Android VPN
service как `AccessControl`.

После успешного создания VPN service сохраняет снимок фактически применённых
правил. Экран контроля доступа показывает этот снимок; если он недоступен,
интерфейс явно говорит, что отображается только декларация текущего профиля.
Изменение package rules требует пересоздания VPN, простой reload ядра их не
применяет.

Если заданный селектор не совпал ни с одним установленным приложением, результат
include превращается в явный режим «не включать ни одно приложение», а результат
exclude — в «ничего не исключать». Полностью пустой `include-package: []` или
`exclude-package: []` не создаёт профильного правила; это отличается от
непустого селектора, давшего пустой результат.
